Menz API

Data-driven REST API for a men's clothing store, built with Node.js, Express and Sequelize.

General notes

  • Base URL: all API endpoints are prefixed with /api.
  • Request bodies are JSON (Content-Type: application/json), except product create/update which use multipart/form-data (to support an optional photo upload).
  • Authentication uses a JSON Web Token stored in an httpOnly cookie named token, set automatically on register/login. There is no Authorization header — clients must call fetch() with credentials: 'include' so the browser sends the cookie.
  • Endpoints marked "Auth: required" respond 401 without a valid session cookie. Endpoints marked "Role: admin" additionally respond 403 for a non-admin user.
  • Validation and other client errors respond with status 400 (or 409 for conflicts) and a body of the form { "errors": ["message", ...] }.
  • Not-found resources respond 404 with { "errors": ["... not found"] }.

Authentication — /api

POST /api/register

Create a new client account and log the user in.

Auth: none

FieldLocationNotes
first_namebodyrequired, no digits
last_namebodyrequired, no digits
emailbodyrequired, valid email, must be unique
phonebodyrequired, Belgian format (e.g. +32 470 12 34 56 or 0470 12 34 56)
streetbodyrequired
house_numberbodyrequired
postal_codebodyrequired, exactly 4 digits
citybodyrequired
passwordbodyrequired, min 6 characters
confirm_passwordbodyrequired, must match password

Response: 201 with { id, first_name, last_name, email, role }, sets the session cookie. 409 if the email is already registered.

POST /api/login

Verify credentials and start a session. Role (client/admin) is detected server-side.

Auth: none

FieldLocationNotes
emailbodyrequired
passwordbodyrequired
remember_mebodyoptional boolean, extends cookie lifetime when true

Response: 200 with { role }, sets the session cookie. 401 with a generic error on invalid credentials (no indication whether the email exists).

POST /api/logout

Clear the session cookie.

Auth: none

Response: 200 with { message }.

GET /api/me

Return the currently authenticated user's profile and role.

Auth: required

Response: 200 with { id, first_name, last_name, email, role, phone, street, house_number, postal_code, city }.

POST /api/password/forgot

Send a password reset email if the address is registered.

Auth: none

FieldLocationNotes
emailbodyrequired, valid email

Response: always 200 with the same { message }, regardless of whether the email exists (prevents account enumeration).

POST /api/password/reset

Reset a password using the token emailed by the forgot-password endpoint.

Auth: none

FieldLocationNotes
tokenbodyrequired, from the reset email link
passwordbodyrequired, min 6 characters
confirm_passwordbodyrequired, must match password

Response: 200 with { message }. 400 if the token is invalid or expired.

Categories — /api/categories

GET /api/categories

List all categories.

Auth: none

Response: 200 with an array of { id, name, code, next_product_number }.

GET /api/categories/:id

Retrieve a single category.

Auth: none

Response: 200 with a category object, or 404.

POST /api/categories

Create a category.

Auth: required — Role: admin

FieldLocationNotes
namebodyrequired
codebodyrequired, 2-10 alphanumeric characters, used as the product code prefix (e.g. TSH)

Response: 201 with the created category.

PUT /api/categories/:id

Rename/update a category. Same body as create.

Auth: required — Role: admin

Response: 200 with the updated category, or 404.

DELETE /api/categories/:id

Delete a category.

Auth: required — Role: admin

Response: 204. 409 if products are still linked to the category.

Sizes — /api/sizes

GET /api/sizes

List the fixed set of sizes (S, M, L, XL, XXL) used across all products.

Auth: none

Response: 200 with an array of { id, name }.

Products — /api/products

GET /api/products

List products. Non-admin requests only ever see active products.

Auth: none (optional — an admin session includes inactive products)

FieldLocationNotes
category_idqueryoptional, filter by category
codequeryoptional, partial (substring) match on product code — search endpoint
limitqueryoptional, maximum number of results — pagination endpoint
offsetqueryoptional, number of results to skip — pagination endpoint

Response: 200 with an array of products, each including its Category and its ProductSizes (with Size and stock).

GET /api/products/:id

Retrieve a single product with its sizes/stock.

Auth: none (optional — an admin session can retrieve inactive products)

Response: 200 with the product, or 404.

POST /api/products

Create a product. Its code is auto-generated from the category's code and an incrementing per-category counter (e.g. TSH-0001).

Auth: required — Role: admin

Body: multipart/form-data

FieldLocationNotes
category_idbodyrequired, must reference an existing category
namebodyrequired
descriptionbodyoptional
pricebodyrequired, positive number
activebodyoptional boolean, defaults to true
photobodyoptional, image file upload
sizesbodyoptional, JSON string encoding an array of { size_id, stock }; stock must be a non-negative integer, size_id must reference an existing size

Response: 201 with the created product, including Category and ProductSizes.

PUT /api/products/:id

Update a product. Same fields as create; omitting sizes leaves existing sizes/stock untouched, providing it replaces the full set.

Auth: required — Role: admin

Response: 200 with the updated product, or 404.

DELETE /api/products/:id

Delete a product and its size/stock rows.

Auth: required — Role: admin

Response: 204, or 404.

Orders — /api/orders

GET /api/orders

List orders. A client only ever sees their own orders (scoped server-side by the authenticated user id); an admin sees every order.

Auth: required

FieldLocationNotes
statusqueryoptional, one of new, processed, completed

Response: 200 with an array of orders (newest first), each including its OrderItems (with Product and Size) and the ordering User.

GET /api/orders/:id

Retrieve a single order. Clients receive 404 for an order that isn't theirs (never 403, to avoid confirming the order exists).

Auth: required

Response: 200 with the order, or 404.

POST /api/orders

Place an order from a set of line items. Stock per product/size is checked and decremented server-side inside a transaction — never trusted from the client.

Auth: required

FieldLocationNotes
delivery_typebodyrequired, "pickup" or "shipping"
streetbodyrequired if delivery_type is "shipping"
house_numberbodyrequired if delivery_type is "shipping"
postal_codebodyrequired if delivery_type is "shipping", exactly 4 digits
citybodyrequired if delivery_type is "shipping"
itemsbodyrequired, non-empty array of { product_id, size_id, quantity }; quantity must be a positive integer

Response: 201 with the created order (status new, total including shipping cost when applicable). 409 if any line item's product is inactive or has insufficient stock — the whole order is rejected, nothing is committed.

PUT /api/orders/:id

Update an order's status. Status only moves forward through new → processed → completed; moving backward is rejected.

Auth: required — Role: admin

FieldLocationNotes
statusbodyrequired, one of new, processed, completed

Response: 200 with the updated order. 404 if the order doesn't exist, 409 on a backward transition.
